# Findings and fix plan (Phase 2, updated with production numbers)

**Evidence is code and migrations plus the production read benchmark and Supabase advisor (2026-11-15).**
Key result: calls sit at the ~190 ms network floor, so on a 304-person gym time is mostly the number of round trips and payload size,
not database work. Phone cold start, `db-stats.sql` queries 1-4 and edge functions are still unmeasured.
Nothing below is implemented. Ordered by expected gain divided by risk.

| #   | Issue                                          | Evidence                                                                                             | Proposed fix                                                                                                                                    | Expected gain                                                                                           | Risk                                                | Proof nothing changed                                                                                                                                    |
| --- | ---------------------------------------------- | ---------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- | --------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Web dashboard ships one 501 kB JS chunk        | `web build`: 500.96 kB, 142 kB gzip, no code splitting                                               | `React.lazy` per page (Members, Attendance, Payments, Exports)                                                                                  | Smaller first load, est. 30-40% less JS before sign-in                                                  | Very low                                            | Same pages and data; `web npm run build`; click-through                                                                                                  |

Recommended order after your go-ahead, re-ranked by the measured numbers: 2 (fewer refetches, including caching the
48 KB exercise library for every role) and 5 (fewer round trips on the home screens) first, because round trips are what cost
time; then 1 (web code splitting); then 6 on the biggest payloads (`gym_people` 136 KB, `gym_attendance` 78 KB, `member_trainers`
41 KB); then 4 and 3 on develop, which matter as gyms grow past this 304-person test gym but will barely show on it. Policy merging
(192 warnings) stays last. Each is its own PR to `develop`.
